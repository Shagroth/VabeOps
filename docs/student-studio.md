# Студия участника — что изменилось (ветка `feature/student-studio`)

Цель: к старту первой группы (5–6 человек) участник заходит на платформу и
видит в одном месте курс, лабораторию, домашнюю работу, сдачу, фидбек и
обсуждение недели.

## Что сделано

| Область | Изменение |
|---|---|
| Публичный demo-курс | Открыты только модули 1–2 (`src/content/demo-access.ts`). `/demo-course/3…5` показывают обложку модуля и блок «для участников пилота»; уроки и ТЗ домашки этих модулей не попадают ни в HTML, ни в клиентский бандл (проверено по `.next` после сборки). Страницы 3–5 — `noindex`. |
| Неделя когорты ↔ контент курса | Новое поле `Module.courseModuleNumber Int?` (миграция `0003`). Если задано, `/modules/[id]` рендерит интерактивный урок, лабораторию и ТЗ домашки из `src/content`, ниже — сдача, фидбек, анкета и обсуждение. Markdown-поля недели остаются как «Заметки автора к неделе». |
| Лаборатория → сдача | Кнопка «Перенести в сдачу ↓» на шаге артефакта кладёт собранный Markdown в поле «Результат» формы сдачи (`src/lib/artifact-bridge.ts`). Лимит поля поднят до 12 000 символов, общий для клиента и сервера. |
| Админка | «Создать недостающие недели из программы» (5 недель, открыта только 1-я, повторный клик безопасен); кнопки «Открыть/Закрыть» у каждой недели; выбор модуля курса в форме недели; блок «Участники»: зачислить по email + имя + уровень, отчислить, сделать/снять ментора. В «Заявках» у принятой заявки — «Зачислить» в выбранную когорту. |
| Приватность | Участники видят друг друга по имени, не по email (Поток, обсуждения, «поделились решением», фидбек). В клиентские компоненты больше не уходят целые строки `User`. Имя редактируется в профиле «Потока»; на обзоре — подсказка, если имени нет. |
| Обзор | «Следующий шаг» с приоритетом: доработка по фидбеку → первая открытая несданная неделя → «все сданы, следующей откроется неделя N» (`src/lib/next-step.ts`). |

## Что добавлено после этого хендоффа (email-уведомления, очередь проверки, баллы)

| Область | Изменение |
|---|---|
| Email-уведомления | Новая сдача/версия → письмо на `NOTIFY_ADMIN_EMAIL` (если задана и Resend настроен — иначе тихий no-op). Решение/фидбек автора → письмо участнику со ссылкой на `/modules/[id]#submission`. Best-effort: ошибка отправки логируется (`submission_notify_sent_failed` / `feedback_notify_sent_failed`), но не ломает сохранение сдачи/ревью. Паттерн и таймаут (8с) — как у `magic-link-send.ts`; email участника/`NOTIFY_ADMIN_EMAIL` маскируются в логах через `maskEmail`. |
| Общая очередь проверки | `/admin/review` — все сдачи в статусе `SUBMITTED` по всем когортам/неделям, самые старые сверху. Доступ: ADMIN и MENTOR (`canReviewSubmissions` в `studio-permissions.ts`; `reviewSubmission` сам проверяет роль на сервере — доступ в навигации не является единственной защитой). Ссылка «На проверке» в сайдбаре видна тем же ролям. |
| Оценка по рубрике | `HOMEWORK_SCORING` (20 баллов, 6 критериев) и `HOMEWORK_PASS_SCORE = 14` в `src/content/demo-course-homework.ts`. Баллы — опционально и только все сразу (`src/lib/homework-scoring.ts` `parseScores`: пусто → не оценено, частично → ошибка, не тихий partial-total). Хранятся как `SubmissionFeedback.scores Int[]`-подобный `Json?` (nullable, миграция `0004`). Участник видит итог, проходной балл и разбивку по критериям в блоке фидбека на `/modules/[id]`. |

## Деплой

- Схема изменилась аддитивно: nullable `Module.courseModuleNumber` (было) +
  nullable `SubmissionFeedback.scores` (миграция `0004`). Pre-deploy на
  Railway — `npx prisma db push` — применит обе без потери данных.
- Новая переменная окружения: `NOTIFY_ADMIN_EMAIL` (опциональная — см.
  `.env.example`). Без неё уведомление о новой сдаче просто не отправляется,
  остальное работает как прежде.

## Ручные шаги после деплоя

1. В Railway → переменные сервиса `web` → задать `NOTIFY_ADMIN_EMAIL`
   (адрес, куда слать уведомления о новых сдачах). Необязательно — без неё
   уведомление участнику о решении всё равно работает, если уже настроен
   `AUTH_RESEND_KEY`/`EMAIL_FROM`.
2. Проверить в Resend, что домен из `EMAIL_FROM` верифицирован (DKIM/SPF) —
   иначе письма участникам/на `NOTIFY_ADMIN_EMAIL` будут падать в спам или
   отклоняться. Это уже требовалось для входа по magic link, но стоит
   перепроверить сейчас, когда писем стало больше.
3. Зайти под ADMIN или MENTOR на `/admin/review` и убедиться, что очередь
   открывается (пустая — это нормально, пока нет сдач в статусе `SUBMITTED`).

## Запуск группы — чек-лист автора

1. `/admin` → создать когорту → «Создать недостающие недели из программы».
2. Зачислить себя (чтобы видеть неделю глазами участника) и участников по email.
3. Добавить созвоны (kickoff/midpoint/final).
4. Открывать недели кнопкой «Открыть» по расписанию.
